## What was proven

- **Immutable files are the truth; the database is a projection.**
  - A publication is written once, atomically, and never overwritten.
  - CI refuses any change to a published file and re-checks each added one: canonical form, citations, overlap, record order and the tool label.
  - The database is emptied and refilled from the files in one transaction, in record order (ADR-0015).
- **Two timelines.** Every query names a record moment; `tariff_version` also names a valid date. A correction or withdrawal changes answers only from its `published_at`. An exclusion constraint refuses overlapping versions at any record moment.
- **Verification is recorded, not assumed.**
  - The owner checked Tariff B and the VAT rate against the source pages (E56). Exactly those values are `verified`: 12 of the 16 cited values in each Tariff B version, and both VAT values.
  - Each of the four remaining estimated cited values says what would confirm it (E57). The rounding and billing policies say what they assume, and that real bills or receipts would settle it (P3).
  - `tests/unit/data/test_ekurhuleni_2026_27.py` asserts that split value by value.
- **The README example runs end to end from published data.** `tests/integration/test_readme_example.py` does three things:
  - rebuilds the test database from the committed `data/`;
  - prices the example through the repository;
  - compares the result with the README.

  `poe db-rebuild` on the development database reports "3 publications (2 tariff versions, 1 VAT rates), 3 source documents".
- **Database access is narrow.** The app role can only `SELECT`. Services reach the database only through `persistence`, and import-linter enforces it. A refused connection and a database without tables or privileges are reported naming the database only, never the URL, host, role or password (`tests/integration/persistence/test_connect.py`); other query errors pass through unchanged, and P5 must wrap them (security register).

- **The Tariff B values are verified by eye only.** The schedule is a scan with no text layer, so the automatic citation check cannot confirm them. The owner accepted "R3.37,00" as R3.37 per kWh. No Ekurhuleni receipt has confirmed it.

- **The guards have known limits** (security register): they run the pull request's own code; Bash can write publications (TD-3); `published_at` is declared by the file (TD-14).
- **Who ran the publish command.** It was run by Claude Code in the owner's session, after the owner's hand check and with the owner's instruction. `published_by: owner` records the owner's approval, not who typed the command.
- **Native Windows** is still untested (WSL2 only, D6).

About OpenSSL 3.5.9:
- Most of its fixes are in DTLS, QUIC, CMP and SM2, which a libpq client does not use.
- At least two are in general TLS or EC code: an out-of-bounds access after `SSL_set_SSL_CTX()` during a handshake, and a timing side channel in scalar multiplication for non-NIST curves. I have not established whether libpq can reach them.
- Today's exposure is nil in practice. The local server has TLS off (`SHOW ssl` = `off`; `pg_stat_ssl.ssl` = false for the app connection), so no MuniSense connection uses TLS. The bundled libcrypto is still used for SCRAM-SHA-256 authentication, which P2-3 forces; the listed 3.5.9 fixes are not known to touch it. It matters before any non-loopback connection (P9).
- Whether psycopg-binary 3.3.9 bundles OpenSSL 3.5.9 is not yet checked.

- **P3 has no confirmed source of golden cases** (W11). This remains the largest risk to the pilot. Every Ekurhuleni policy and VAT treatment is an assumption until real Ekurhuleni bills or receipts arrive.
- **Bundled native libraries lag upstream.** OpenSSL is one security release behind, and the older bundled builds are unverified. This is harmless while connections stay local and unencrypted. It becomes a deployment blocker if not addressed by P9.
- **`poe check` is at 24.4 s against a 25 s limit.** P3 and P4 tests will push it over. E43 already says what happens then: move the slowest property tests behind `slow`.
- **Hand verification does not scale.** Every scanned schedule needs the owner's eye, and P3 adds the 2025/26 schedule.
- **Next phase:** P4 changes the domain, so mutation testing must be re-run at its gate. Whether mutmut writes caches under the repository folder should be checked then (#40 re-review).
