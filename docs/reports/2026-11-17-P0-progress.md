### Commands for the owner to run

**Recommendation: use the `Ubuntu` (24.04) distribution, not `Ubuntu-22.04`.** It matches the README, and it has a normal user. Working as `root` makes every file and tool root-owned and removes a safety layer. (Option B, adding a non-root user to `Ubuntu-22.04`, works too but is more steps.) Your existing `Ubuntu-22.04` setup can stay as it is; nothing below deletes it.

In **PowerShell** (not as administrator):

```powershell
wsl --set-default Ubuntu
```

Then open **Ubuntu** and run:

```bash
sudo apt update && sudo apt install -y git unzip build-essential gh
curl -LsSf https://astral.sh/uv/install.sh | sh
exec $SHELL
uv python install 3.13
git config --global user.name "<name for commits>"
git config --global user.email "<email for commits>"
gh auth login            # choose GitHub.com, HTTPS, browser login
gh auth setup-git
curl -fsSL https://claude.ai/install.sh | bash
exec $SHELL
which claude             # must print /home/flosh/.local/bin/claude, NOT a /mnt/c/... path
echo "alias munisense='cd /mnt/c/MuniSense/MuniSense && export UV_PROJECT_ENVIRONMENT=\$HOME/.venvs/munisense'" >> ~/.bashrc
exec $SHELL
munisense && claude
```

If `which claude` still shows the Windows `/mnt/c/.../npm/claude` shim, the Linux install is not first on `PATH`; run `export PATH="$HOME/.local/bin:$PATH"` and add that line to `~/.bashrc`.

Optional clean-up on Windows (it is harmless to the WSL setup, but it breaks `uv python find` on Windows): `choco uninstall python313`, or delete the stale shim.

After setup, P0-1 should be re-run from inside WSL to produce clean evidence.
