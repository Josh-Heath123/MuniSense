## Risks and concerns

- **The main controls are human.** There is no branch protection on the free plan, so pull requests, CI and the owner's merges are the real controls. CI is not a merge gate; Claude Code merges only on green (E17). The local hooks are best-effort, with documented gaps.
- **Secret scanning detects; it does not prevent.** CI scans after the push, so a secret could reach GitHub before it is caught. Rotation, and possibly a history rewrite, would then be owner decisions. The default gitleaks rules also miss low-entropy passwords in connection URLs (security document, secret-scanning row).
- **The local database user is a PostgreSQL superuser.** This is harmless today: the server is bound to localhost and the password is a throwaway. From P2, the app and tests must connect as a non-superuser role (P2 note in `status.md`).
- **Reviews keep finding real defects.** Every reviewed pull request had at least one should-fix or blocking finding, for example:
  - a case-sensitivity regression in the ADR guard on `/mnt/c`;
  - a wrong import contract that would have broken the intended architecture;
  - a pre-push claim that went beyond what the hook does;
  - this report's own first draft, which overclaimed in several places.

  The reviews are earning their cost. A first draft from me should not be trusted without them.
- **Docker is on the commit path.** The gitleaks hook needs Docker running to commit. Docker's Windows credential helper failed once.
- **Real bills from P3 onwards.** pre-commit stashes unstaged changes in `~/.cache/pre-commit/`, so originals must stay in git-ignored `data/private/`.
